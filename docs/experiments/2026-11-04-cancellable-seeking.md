# Cancellable seeking qualification

Issue: [DJ-039](https://github.com/coder13/Fader/issues/39). Status: implementation, local correctness/lifetime tests and timing measurements passed for the cached path. Clean CI and native visual verification remain pending. Uncached long MP3 misses the interactive targets; that fallback stays explicitly slower and cancellable. No audio device/controller is used in these measurements.

## Configuration and targets

Local Apple Silicon arm64, Darwin 25.6.0/macOS 26.6.2, AppleClang 21.0.0.21000334, CMake 4.4.4, Release/C++20; JUCE 9.0.5 at `d60b7a78030661574a615b586d9325ba7a7fa7dd`. Implementation: `c9dba8c0407eccbf7dfd93998d197f40127a87db`. Measurements used the staged Release implementation committed there; the final pre-commit changes were comments and the fixture recipe, with no renderer/cache/preparation behavior changes. The new concurrency tests also passed in a standalone Apple ThreadSanitizer build.

The [contract](../seek-contract.md) set warm p95 ≤150 ms, cold p95 ≤500 ms and absolute PCM/control error ≤1e-5 before measurement (initial targets commit `802ace0`). “Cold” here means a first visit to a destination using fresh engine/decoder readers, after import; “warm” means its immediate repeat, also using fresh readers. The OS file cache is **not purged**. This is not storage-cold latency, device latency or a platform-wide performance promise.

The probe uses 40 first-visit/repeat pairs, visiting destinations in a fixed coprime order. Timing begins at the request and ends when polling accepts the current generation; it includes retirement of an earlier engine. Completion is polled every 1 ms. The native UI polls at 30 Hz and can add a timer tick. Import, validation, PCM-cache creation, first UI snapshot copying and initial device setup are outside these seek timing figures. No local build, sanitizer run or encoder ran concurrently with timing.

Each clip skips two source seconds, yielding a 2 h 44 m 58 s arrangement. Seek positions span the overlap. Sparse silence/bursts do not represent worst-case continuous music or storage.

The OS may keep file data in reclaimable cache; the page budget is not a total system-memory cap.

The uncached path preserves readable MP3 support when temporary storage cannot be admitted/written. It is not a passing fast-seek result. UI preparation text identifies it, and Cancel remains available. The cached path meets both declared targets on these fixtures.

## Correctness, cancellation and bounds

- `seeking` compares two 20-second two-clip projects against uninterrupted rendering at 11 destinations each. It covers rates 8–384 kHz, speeds 0.25–4, delayed starts, nonzero source offsets, ramps, holds and filter bypass boundaries. Maximum absolute master/cue PCM and prepared volume/HP/LP errors were both **0**, inside the 1e-5 contract. This validates the current simple filters on the declared normalized fixtures; it is not a universal bit-exact guarantee for future effects.
- A blocked cooperative decoder exits when preparation is cancelled. A separate factory deliberately ignores cancellation and returns a late success: 1,000 superseding requests, cancellation and source replacement still publish only the latest project/position. Only two builds run in that fixture (the initial blocked job and the final request).
- Closing during a delayed failure yields no completion. A decoder destructor deliberately stalls; Cancel and a new request return without waiting, and the next engine is built only after retirement releases. All engine destruction/decoder joins stay on the preparation worker. The test guards these control operations with a one-second CI timeout, not a claim of measured sub-millisecond UI latency.
- A targeted ThreadSanitizer build of Engine, Streaming, Playback, PlaybackPreparation, SeekTests and PreparationTests passes without a race report. This is not a whole-app sanitizer result.
- Native cache tests verify the 8 GiB aggregate admission/release limit without writing a huge test file, two concurrent readers at different positions, cancellation, overflow-safe offsets, source modification/deletion rejection and cached/uncached VBR parity. Session cache files are not serialized.
- Full sequential comparison of both 30-minute MP3s with an independent decoder, followed by 14 forward/backward/tail windows each, reports **0** sequential and seek sample error. Local native CTest passes **5/5**, including callback allocation regression fixtures.

The two-second filter reconstruction policy is specific to the current smoother and stable one-pole HP/LP stages. Future stretch, delay/reverb, resonance and plugins require their own state/checkpoint/tail policies. OS reads can outlive cancellation; the worker retains storage until they return, so a later seek may wait even though the UI can invalidate it. General import/export/library cancellation, large-session UI scalability, continuous load, Windows native execution and hardware latency remain separate work.
